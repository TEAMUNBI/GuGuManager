# ADR-0002：开发数据根的混合生命周期

- 状态：accepted
- 日期：2026-08-07

## 背景

开发 Control Plane 的服务器、会话、operation、备份元数据和审计使用内存适配器，进程重启后恢复固定种子状态。文件功能需要真实验证路径边界、原子替换和跨请求读写，因此每台服务器同时拥有 `GUGU_DEV_DATA_ROOT/<server-id>` 本地目录。

动态创建的服务器使用随机 ID。进程重启后对应内存服务器记录消失，但目录仍可能包含开发者需要检查的数据；仅凭新的内存状态无法证明旧目录可以安全删除。

## 决策

- 开发服务器文件跨 Control Plane 重启保留，其他开发控制面状态继续重置。
- 固定种子服务器在重启后重新挂接相同 ID 的目录。
- 动态服务器遗留目录不自动回收，也不由启动流程猜测所有权。
- 人工清理只能在 Control Plane 停止后进行，并由操作者先确认目标位于专用开发根且没有需要保留的数据。
- `GUGU_DEV_DATA_ROOT` 不得指向生产游戏数据、共享目录或其他应用目录。
- 生产实现由 PostgreSQL 服务器生命周期、Agent 数据根和显式删除 operation 共同决定回收，不沿用该开发策略。

## 后果

- 文件安全行为可以在没有 Docker、Agent 和数据库时使用真实文件系统验证。
- 开发者重启面板不会意外丢失文件编辑结果。
- 多次创建动态服务器会产生不可达目录并占用磁盘，当前没有自动清理命令。
- README、本地开发指南和运维章节必须明确这种混合生命周期，不能再笼统写“进程退出清空全部开发数据”。
