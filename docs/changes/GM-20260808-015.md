# GM-20260808-015：Operation 节点快照与完成栅栏

日期：2026-08-08

## 变更范围

本轮补齐设计和 PostgreSQL `server_tasks` 骨架已经要求、但开发领域模型与 API 尚未实现的 `Operation.nodeId`。该字段定义为 operation 受理时不可变的执行节点快照，并参与终态提交校验，避免服务器节点归属变化后旧任务错误成功或提交副作用。

## 已实现

- `domain.Operation` 与统一 queued 构造器新增必填 `nodeId`；简化 PowerCoordinator 也要求调用方显式提供节点。幂等回放返回原 operation，不从服务器当前状态改写节点。
- provision 从已验证的创建节点取快照；电源、备份创建、恢复和备份删除从受理时 Server 取快照；Network/Startup reconcile 从已验证节点取快照。
- 通用终态辅助函数同时校验服务器存在、generation 相等和节点快照相等；恢复路径同步加入节点校验。备份删除改用相同栅栏，失败时保留并恢复 recovery point 的 `ready` 状态。
- 恢复和备份删除先校验 Server 存在、generation 与节点快照，再判断摘要或备份是否存在；组合失败优先返回不可重试的 `OPERATION_STALE`，stale 恢复/删除只把仍存在的临时 recovery point 补偿回 `ready`。
- OpenAPI 将 `nodeId` 定义为 Operation 的必填 UUID；生成 TypeScript、手写类型、所有严格 Operation fixture、Mock 和独立 Power 模型已同步。
- development-memory Web Mock 的 provision、电源、备份创建、恢复、备份删除和 reconcile 统一使用 Server 存在、generation 与 `nodeId` 完成栅栏；stale operation 进入结构化 failed 终态，且只有 succeeded 才提交资源副作用。恢复受理时先推进 Server generation，恢复/删除 stale 时把 recovery point 恢复为 `ready`。
- HTTP 原始 JSON 回归要求 queued operation 返回正确的 `nodeId`；真实 HTTP 和 Web Mock 的 operation 查询都按 `serverId` 与当前 `servers.read` 授权，membership 撤销后立即拒绝读取，`nodeId` 不作为授权凭据。
- 备份创建、恢复、删除和 reconcile 到达终态后均写入结果审计；若 Server 已不存在，则使用稳定的 `serverId` 作为审计目标名称并记录 `failure`。
- `DESIGN.md` 文档版本更新为 `0.8.0`；领域模型、API 契约和测试路线图明确节点快照、幂等回放和跨节点 stale 语义。

## TDD 与 mutation 证据

- 红灯阶段，Go 测试因 `Operation.NodeID` 和 PowerCoordinator 节点参数缺失而编译失败；HTTP 回归报告原始 JSON 缺少 `nodeId`；Mock 回归观察到 `operation.nodeId` 为 `undefined`。
- 绿灯阶段，六类当前可受理 operation 均返回正确节点快照，HTTP 与 Web 类型契约同步通过。
- 临时把 Go queued 构造器的节点置空后，领域幂等测试、六类 Store 受理子测试和 HTTP JSON 测试全部失败；恢复后转绿。
- 临时移除通用与恢复专用的节点比较后，电源错误落地为 running、恢复错误进入 succeeded、备份删除错误移除 recovery point；三个节点漂移回归均失败，恢复实现后转绿。
- 临时把 Web Power 与 Mock provision 的节点置空后，对应两个 Vitest 均按预期失败；恢复后相关 96 个测试通过。
- 审查修复红灯阶段，stale restore 与损坏摘要组合错误返回 `BACKUP_INTEGRITY_FAILED`，stale delete 与备份缺失组合错误返回 `OPERATION_FAILED`；Server 缺失时 4 类终态审计均未新增事件。修正完成顺序和审计 fallback 后，目标 Go 回归转绿。
- Web Mock 六类 stale 回归在修复前全部观察到错误的 `succeeded/completed` 终态；operation membership 撤权回归也观察到查询错误成功。接入共享完成栅栏和 `serverId` 授权后，7 个回归全部转绿。
- 临时让 Go 目标匹配恒为真后，2 个组合优先级回归失败；临时恢复 `serverOK` 审计门槛后，4 个 Server 缺失子用例失败；临时跳过 Web generation/节点比较后，六类 stale 回归全部失败；临时跳过 `canReadServer` 后，撤权回归失败。所有 mutation 均已立即恢复并重新转绿。

## 验证与边界

本轮完整验证命令：

- `go test ./... -count=1`
- `go vet ./...`
- `go run ./cmd/migrate -dir migrations plan`
- `npm test -- --run`
- `npm run typecheck`
- `npm run build`
- `npm run api:lint`
- `npm run api:check`
- `npm run e2e`

最终验证结果：Go 格式无差异，Go 全包测试与 Vet 通过；迁移计划验证 3 对 migration，明确为 dry-run，未连接数据库或执行 SQL；Vitest 12 个测试文件、167 个测试通过；TypeScript 类型检查、生产构建、OpenAPI lint 和生成漂移检查通过；Chromium 在真实 development-memory Go Control Plane 上的 1 个 E2E 用例通过。当前机器的 Go 不在系统 `PATH`，E2E 通过仅在该验证进程中前置已确认的 Go 工具目录完成，没有修改系统环境。

当前没有服务器节点重分配或迁移 API，也没有 DeleteServer operation。开发备份没有独立的制品执行节点，因此 backup-delete 暂时固定服务器受理时节点；生产对象存储删除或跨节点迁移必须显式定义执行器或拆分源/目标节点子任务，不能把 `nodeId` 改成 nullable。当前内存 operation 无持久升级问题；未来已有持久任务的部署必须通过 migration 回填并校验 `server_tasks.node_id`，不得在读取时从服务器当前节点静默推导。
