# GM-20260808-011：浏览器 E2E 与开发镜像制品门禁

日期：2026-08-08

## 变更范围

本切片为构建后的 Web 与真实 Go Control Plane 建立可重复的 Chromium 端到端验证，并把同一 commit 开发镜像的启动烟雾测试、漏洞报告、CycloneDX SBOM 和可修复高危漏洞门禁写入 CI。它不把 development-memory 容器称为生产发布，也不声称本机已经执行 Docker 或 GitHub Runner。

## 已实现

- 固定 `@playwright/test 1.62.1`，提供 `e2e` 与本地交互调试用 `e2e:ui`，两条命令都由对应 npm pre-script 构建 SPA；单 worker Chromium 使用 `127.0.0.1:18080` 同源启动 Go Control Plane，拒绝复用已有服务，operation latency 为 `0s`，服务器文件隔离到 `web/test-results/run/server-data`。
- E2E 从 `/servers` 深链进入，断言未登录跳转、真实 setup/status `200`、session `401`、login `200`、servers 列表 `200`、固定“雾港生存服”详情 `200` 和 logout `204`。每项关键响应都必须来自同源 `/api/v1/*`，浏览器 Mock 无法满足测试。
- Playwright 保留失败截图、视频、首次重试 trace 和 HTML 报告；Vitest 使用默认排除集合加 `e2e/**`，两个 runner 不再互相收集测试。浏览器 job 在安装依赖前写入 Go/Node/npm/Runner 元数据，因此较早失败仍有可上传证据。
- CI 新增 15 分钟浏览器 job：Go 1.26、Node 24、`npm ci`、官方 CLI 安装 Chromium、执行 `npm run e2e`，并在非取消状态下保留 7 天测试证据；CI 可重试失败场景以收集 trace，但 `failOnFlakyTests` 会让首次失败、重试通过的 flaky 场景仍阻断门禁。
- Web 构建镜像从已结束维护的 Node 25 改为官方存在的 `node:24.18.0-alpine3.23` 标签；Playwright 临时结果同时加入 Git 与 Docker context 忽略。
- `development-container` job 对同一 `gugumanager/control-plane-development-preview:${{ github.sha }}` 只构建一次，回环启动时显式选择 development，随后以单次连接/请求超时轮询 `/readyz`，断言 development-memory adapter 与 SPA 标题；失败输出容器日志并始终删除测试容器。
- 镜像自身默认 `GUGU_ENVIRONMENT=production`，在生产适配器尚未实现且生产配置不完整时 fail closed；开发 Compose 与 CI 必须显式选择 development，避免把裸 `docker run` 误当成生产可用服务。
- 固定 Trivy Action 安全 commit `ed142fd0673e97e23eac54620cfb913e5ce36c25`、Trivy `0.72.0` 和报告上传 Action commit `ea165f8d65b6e75b540449e92b4886f43607fa02`。同一镜像生成完整漏洞 JSON 与 CycloneDX JSON，并对已有修复版本的 HIGH/CRITICAL 漏洞返回失败；镜像/容器 inspect、日志、ready 响应与首页也进入 7 天证据包。

## TDD、Mutation 与验证结果

- 无 `webServer` 时，E2E 在 `/readyz` 以 `ECONNREFUSED` 红灯；接入真实 Go 服务后转绿。
- 临时让服务端管理员口令与测试口令不一致时，登录响应由预期 `200` 变为 `401`，证明真实后端失败不能由 Mock 掩盖；恢复后通过。
- Vitest 未排除 `e2e/**`，或把排除模式突变为不匹配值时，稳定以 Playwright context 错误失败；恢复默认排除集合加 E2E 模式后通过。
- `npm run e2e`：Chromium 151.0.7922.34，1/1 场景通过；服务日志命中 setup、session、login、servers、server detail 和 logout；退出后 `127.0.0.1:18080` 已释放。
- 应用内浏览器另在 `127.0.0.1:18082` 验证深链登录、Control room、种子服务器详情与退出；页面控制台无 error，受控服务随后终止并确认端口释放。
- `npm test`：10 个测试文件、84 个测试通过；`AppIdentity.test.tsx` 为 20/20。
- `npm run typecheck`、`npm run api:lint`、`npm run api:check`、`npm run build`：通过；`npm audit --audit-level=high` 为 0 个漏洞。
- `go test ./... -count=1`、`go vet ./...`、三份 GameDefinition lint、Buf format/build/lint/baseline breaking、Protobuf 重生成哈希稳定与 `govulncheck v1.6.0 ./...`：通过。
- `actionlint v1.7.12` 对包含浏览器与容器 job 的工作流静态校验通过。

## API、数据与安全影响

- REST API、OpenAPI、权限键、迁移 SQL 和生产配置没有变化。
- E2E 使用公开、仅用于本地测试的开发凭据；CI 不读取部署 Secret、不使用 `pull_request_target`、不推送镜像。Git 与 Docker context 默认排除各目录下的 `.env` 和 `.env.*`，只允许显式 `.env.example` 样例进入版本与构建上下文。
- 镜像运行时仍是非 root UID `10001`。CI 显式启动的只是开发内存适配器，裸镜像默认 fail closed；报告和 SBOM 是 CI 证据，不是签名、来源证明或发布 attestation。

## 未完成或未验证范围

- 本机没有 Docker，因此没有在本机真实构建、启动或扫描镜像；工作区没有 `.git`，也没有 GitHub run。`development-container` job、Trivy 和 SBOM 当前只有静态配置与 `actionlint` 证据，不能写成已远端通过。
- 基础镜像使用精确版本标签但没有固定 OCI manifest digest；仍需依赖更新机器人、镜像签名、来源证明和发布 attestation。
- 没有 Firefox/WebKit、真实 PostgreSQL/Redis Store、多副本会话、真实 Agent/Docker Runtime、游戏完整生命周期或生产发布 E2E。
- Trivy 门禁忽略没有修复版本的漏洞，以避免无解阻断；完整 JSON 仍保留这些发现，发布方必须审阅而不能只看门禁结果。
