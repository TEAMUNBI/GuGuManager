# GM-20260808-013：Identity、撤权与 API 契约加固

日期：2026-08-08

## 变更范围

本轮复核此前多个实现子任务的交集，不把“单元测试通过”视为授权、并发和契约已经正确。变更集中在开发内存 Store 的身份与撤权边界、HTTP JSON 输入约定、production 配置拒绝项、PostgreSQL membership permission migration，以及 OpenAPI／前端生成类型同步。

## 已实现

- 登录限流改为 reservation：账号与直接来源 IP 的 in-flight 尝试也占用阈值，成功只清理账号维度；setup 与密码重置使用独立来源 IP reservation。Argon2id 派生使用进程级并发门，最多同时执行 2 个任务。
- setup 与 password reset 在执行 Argon2 前验证 Bootstrap/reset Token 的摘要、TTL 与消费状态，并在提交前再次验证。停用用户会撤销内存 session 和全部未消费 reset token，因此停用后重新启用不会使旧 token 复活。
- Store 的创建服务器、电源、Network、Startup、控制台、备份和文件写入在副作用、active operation 复用或幂等 replay 前重新读取当前用户和 membership；不再信任 HTTP session 的旧 `domain.User` 快照。文件写入、建目录、移动和删除持有服务器门控及 Store 写锁直到物理操作完成，避免撤权后的本地磁盘副作用。
- JSON body 端点只接受 `application/json`（允许 charset 参数），其他 media type 返回 `415 UNSUPPORTED_MEDIA_TYPE`。匿名 setup、登录和密码重置 body 限制为 64 KiB，其他当前 JSON body 保持 12 MiB 上限。
- `Config.Validate()` 与环境加载共同拒绝 production 配置中的 `GUGU_DEV_BOOTSTRAP_TOKEN`。
- 新增 `000003_membership_permissions`：`server_members.permissions text[]` 必须非空、包含 `servers.read`、没有 `NULL` 或重复项，并且只能使用稳定的 13 个服务器权限。升级时补齐历史缺失的 `servers.read`；含未知或重复权限的历史数据会导致事务回滚并要求显式修复。down migration 只撤销约束与辅助函数，不撤销补齐的数据。
- OpenAPI 补齐实际 `403`、新的 `415`、Startup 读取的 `422`，并纳入 development-only 的 `/dev/agent/heartbeat` 契约；前端 `openapi.generated.ts` 已重新生成。

## TDD 与 mutation 证据

- 文件撤权测试覆盖 WriteFile、CreateDirectory、MoveFile 和 DeleteFile：撤销 membership 后不得产生任何文件、operation、generation 或审计副作用。临时短路 `beginFileMutation()` 的授权 guard 后，四个子用例都错误地成功；恢复后转绿。
- Content-Type 回归先证明旧实现会接受缺失或 `text/plain`；新增 `415` 映射后转绿。临时短路专用错误映射分支时，端到端登录从 `415` 回落到 `422`，测试重新失败。
- 匿名 body 上限回归使用“合法登录 JSON 加尾随空白”：旧 12 MiB 路径返回 `200`，64 KiB 限制后返回 `422`。临时让匿名解码复用通用上限时，测试重新返回 `200`。
- 直接构造 production `Config` 的回归先观察到 `Validate()` 返回 `nil`；增加禁止项后转绿。临时短路 production 分支时，测试重新失败。
- PostgreSQL 集成测试新增 legacy 空权限 membership 回填、缺少 `servers.read`、未知、重复和 `NULL` 权限拒绝，以及 down migration 后约束移除。测试只允许名称以 `_test` 结尾的显式数据库，并使用唯一 schema。

- `npm run e2e` 首次失败是因为 Playwright 的 webServer 进程找不到 `go`；在当前命令里临时补上 Go 缓存目录到 `PATH` 后复跑通过。该问题是本机环境路径问题，不是应用逻辑失败。
- PostgreSQL migration 动态测试在本机未设置 `GUGU_TEST_DATABASE_URL` 时按设计明确 Skip；这不构成真实 SQL 执行证据。
- 当前仍是 development-memory Store。PostgreSQL Identity Store、Redis 分布式限流、跨副本 session／撤权、实时连接关闭、Agent mTLS/gRPC、OCI Runtime、持久任务／Outbox、真实端口绑定与真实备份均未实现。
- 文件与撤权的互斥只保证撤权后新提交的物理文件副作用不会发生；撤权前已经受理的异步 operation 不会被当前开发适配器主动取消。
