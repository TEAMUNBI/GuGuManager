# GM-20260808-007：恢复期间文件变更门控

日期：2026-08-08

## 变更范围

本切片补齐开发 Store 中“恢复登记”和文件系统变更之间的竞态，使同一服务器的恢复与写入、建目录、移动、删除不能穿过彼此的检查窗口。

## 已实现

- Store 为每个服务器维护独立的文件变更门控；不同服务器不因全局锁而互相阻塞。
- `RestoreBackup` 在检查互斥状态到登记 active restore operation 的整个窗口持有写门控。
- 文件写入、建目录、移动和删除在“检查是否有恢复”到实际文件系统副作用完成的整个窗口持有读门控。
- 恢复已经活动时，文件变更返回 `409 OPERATION_IN_PROGRESS`，错误详情包含现有 operation ID 与类型。
- 门控只在短暂状态检查时进入 Store mutex，不在文件 I/O 期间持有全局 Store 锁。

## API、数据库与权限影响

- HTTP 路由、请求体与权限键没有变化；原有结构化冲突码现在覆盖此前存在的并发窗口。
- 没有数据库变化。锁是单进程、每服务器的开发适配器机制，不是持久租约或跨副本互斥。

## 验证结果

- Store 与 HTTP 回归测试先证明恢复检查窗口内的文件操作曾错误成功，再由门控实现转绿。
- 对绕过门控的 mutation 会使并发回归测试重新失败；恢复实现后通过。
- `go test ./... -count=1`：全部 Go 包通过。
- `go vet ./...`：通过。
