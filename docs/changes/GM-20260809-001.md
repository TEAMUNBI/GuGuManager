# GM-20260809-001：阶段 1 真实垂直能力（Postgres + mTLS Agent + Docker）端到端验收

日期：2026-08-09

## 变更范围

把阶段 1 的控制平面 + PostgreSQL 持久化 + 真实 mTLS/gRPC Agent + Docker PaperMC 执行链路部署到生产服务器（面板 103.42.182.201，面板服务器兼作 Docker 节点），完成端到端验收：全新环境接入节点、创建可运行 PaperMC 服务器、电源操作真实执行、节点离线对账与关键操作持久审计。

## 已实现

- **provision payload 落库**：`CreateServer` 构造 provision 任务时把 gameDefinitionId、资源限制、端口分配、启动变量写入 `server_tasks.checkpoint`（此前一直为空，导致 Agent 收到空 payload 全部失败）。字段名与 protojson 反序列化 `ProvisionTaskPayload` 对齐（camelCase）。
- **生命周期推进**：`CompleteTask` 处理成功的 provision 时把服务器 `lifecycle_state` 推进到 `ready`，失败保持 `provisioning` 供上层重试/处置。此前服务器停在 `provisioning` 无法接收电源操作。
- **Docker bind 目录预创建**：Agent `executeProvision` 在 `CreateContainer` 前 `os.MkdirAll` 数据卷根目录（Docker 29 不再为不存在的 bind 源目录自动建目录）。
- **Agent CA 密钥兼容**：`internal/agentca.parseCA` 同时支持 PKCS#1（`RSA PRIVATE KEY`）与 PKCS#8（`PRIVATE KEY`）块类型，兼容 OpenSSL 3.x 默认输出。
- **迁移目录可覆盖**：`migrationsDir()` 优先读取 `GUGU_MIGRATIONS_DIR` 环境变量，解决交叉编译后 `runtime.Caller` 固化 Windows 路径导致服务器找不到迁移目录的问题。
- **电源任务归一化**：`claimedTaskToProto` 把 `server_tasks` 中的 `start/stop/restart/kill` 统一归一化为 Agent 侧 `Type="power"` 并填充 `Power` 字段（含动作与优雅停机超时）；Agent 执行器只按 `provision/power` 分发，此前直接透传 `task_type` 导致电源任务全部 `UNSUPPORTED_TASK`。
- **Postgres 节点离线对账**：新增 `Postgres.ReconcileNodeLiveness`（30 秒心跳超时，维护模式豁免），把过期节点标记 `offline` 并传播到其下所有服务器 `node_condition`；`main.go` 的存活对账协程改为接口断言，Production（Postgres）下启用，与 Memory 版语义一致。配套集成测试 `TestPostgresReconcileNodeLiveness`。
- **服务器端部署工具**：`var/e2e/` 新增 `deploy_agent.sh`、`power_server.sh`、`offline_test.sh` 与 `q_cleanup*.sql` 等验收脚本（该目录已被 `.gitignore` 忽略，不入库）。

## 端到端验收结果（服务器 103.42.182.201）

- 全新环境接入：Agent mTLS 连接 `ad36ac57-51a6-4281-8229-757176122d45` connected；创建 paper-05（`1dfc55f4-…`）→ provision 任务 `succeeded` → 容器 `gugu-server-1dfc55f4-…` 运行（25569/tcp）→ `lifecycle_state=ready`。
- 电源操作真实执行：`stop` 成功（容器 Exited、`desired/observed_power=stopped`）；`start` 成功（容器 Up、`running/running`）；`restart` 成功（容器重启、状态收敛）。
- 重复创建无端口冲突：paper-06（`f1efbf7a-…`）分配 25570/tcp，与 paper-05 的 25569 并存，两容器同时运行，allocations 无重复绑定。
- 节点离线对账：停 Agent 42 秒后节点 `condition=offline`，创建服务器返回 `NODE_OFFLINE`（"节点当前不可接收新任务"）；恢复 Agent 后心跳将节点拉回 `available`。
- 关键操作持久审计：`audit_events` 记录 `auth.login`、`server.power.start/stop/restart`、`task.complete` 等 31+ 条事件。
- Web 全程真实数据：provision/电源均由 Agent 真实执行并回传 Observed，无 memory 模拟。
