# GM-20260808-012：GameDefinition 启动变量契约收敛

日期：2026-08-08

## 变更范围

本切片把 `variables.schema` 从任意 object 收紧为 Control Plane 实际可执行的 closed-object 子集，消除“`gamectl lint` 通过但 Store 启动失败或静默忽略约束”的假绿。同时关闭 Secret `const`/`enum` 候选回显，并让缺少 required 启动变量的 Start/Restart 在任何状态变化前失败。

## 已实现

- Canonical Draft 2020-12 Schema 新增本地 `$defs`，变量 property 只允许：
  - string：`default`、`const`、非空唯一字符串 `enum`、`minLength`、`maxLength`；
  - integer：`default`、`const`、`minimum`、`maximum`；
  - boolean：`default`、`const`。
- `spec/game-definition` 新增共享严格解码与语义校验：按 JSON 成员名精确大小写拒绝未知/类型不适用关键字、null 结构字段、非法 identifier、重复或悬空 required/Secret、矛盾范围、非法 default/const、空或重复 enum，以及超出 JavaScript 安全整数域的值。整数使用精确有理数解析，接受 `15`、`15.0`、`1.5e1` 等数学整数表示，但不会把高精度小数经 binary64 舍入后误收为整数。
- `gamectl lint` 与 Store 固定 Bundle 物化复用同一校验；CLI 会读取 argument binding template，并要求它包含精确的 `{{ value }}` 渲染槽位。Store 还保留 `variables`、`schema`、`secrets`、`bindings` 的缺失/null/错误形状差异，并严格检查 binding 字段、target、environment name 和规范 file path。绕过 lint 的篡改定义统一返回 `PACKAGE_INCOMPATIBLE`，不会忽略 `pattern` 等未实现约束。
- Secret property 禁止在 Bundle 内声明 `default`、`const` 或 `enum`。Store public view、HTTP handler 最后边界和 Web Mock 都会无条件省略 `value`、`default`、`constValue`、`enumValues`；OpenAPI 3.1 用 conditional 对四个字段建立机器约束。
- Startup integer 的公共范围统一为 `-9007199254740991` 至 `9007199254740991`。HTTP 解码保留 `json.Number`，Store 更新、固定 Bundle default/const、OpenAPI 请求与响应、Web 表单和 Web Mock 使用同一安全域；等价的整数 JSON 词法会在计算幂等摘要前规范为同一个值。
- Store 与 Web Mock 的 Start/Restart 在创建 operation、写入新幂等记录、递增 generation、改变 power 或写 accepted audit 前检查全部 required 值。缺失时返回 `VALIDATION_FAILED`，诊断只列变量 key，不包含值。
- Web Mock 对已导入 Bundle 对象执行完整闭集、约束、Secret 和 binding path 二次校验，并保留 required 值齐全时 Start 成功的正向用例。由于 JavaScript JSON 导入已丢失原始 number 词法，原始高精度整数正确性仍由 `gamectl lint` 负责，不能宣称 Mock 与原始 JSON 逐字节同构。
- 三份内置 Bundle 内容、`metadata.version` 和摘要均未修改；现有定义继续通过 lint。

## TDD 与 Mutation 证据

- CLI 红灯覆盖 unsupported number/array/object/union type、`pattern`/`format`/composition、类型不适用关键字、负长度、空/重复 enum、非法 identifier、重复 required、矛盾范围、default/const 违反约束、Secret const/enum 和非安全整数。实现 canonical + 共享校验后全部转绿。
- Store 篡改 Bundle 红灯证明 `pattern`、Secret const/enum 和非安全整数此前会被物化；共享校验接入后统一返回 `PACKAGE_INCOMPATIBLE`。
- Secret public-view 红灯分别观察到 const/enum 元数据泄漏；Store、HTTP 与 Mock 各自脱敏后转绿。临时恢复任一 `constValue`/`enumValues` 输出，对应测试重新失败后已恢复。
- Start 与 Restart 红灯证明 required 缺值此前仍会受理 queued operation；preflight 后转绿，并断言 server generation/power、operation、idempotency 和 audit 全部不变。临时跳过 preflight 后两项测试重新失败并已恢复。
- 安全整数红灯证明正负相邻超界值此前被接受；Store 与 Mock 门禁后转绿。临时放宽为普通 integer 后超界测试重新失败并已恢复。
- HTTP 原始 JSON 红灯证明高精度小数此前可先被 float64 舍入并返回 202；启用 `UseNumber` 和精确整数解析后返回 422。另一个回归证明 `15`、`15.0` 与 `1.5e1` 在同一幂等键下复用同一 operation。
- Web 表单红灯证明高精度小数和相邻非安全整数此前会经 `Number(...)` 静默改变后提交；先校验十进制整数词法再执行 `Number.isSafeInteger` 后，二者都不会调用更新 API。
- Store variables 容器、binding wire DTO 与 Web Mock 完整畸形矩阵先出现定向红灯；严格解码后转绿。Mock 分别移除 `default: null`、矛盾 integer range、`enum: null` 和 file path 规范化防线时，对应用例重新失败后均已恢复。
- CLI argument binding 红灯证明空 template、硬编码 template 与非精确 `{{value}}` 此前会 lint 通过而在 Store 失败；解码 template 并要求 `{{ value }}` 后转绿，临时撤掉门禁时三个反向用例重新失败后已恢复。
- 临时移除 CLI/Store 的共享 `Validate` 调用时，矛盾 default/const 与 Secret material 用例重新假绿；恢复后定向测试通过。

## API、数据、安全与兼容性

- OpenAPI `StartupVariable` Secret 响应契约新增 `constValue`/`enumValues` 禁止条件；共享 `StartupScalar` 把响应 `default`/`value`/`constValue` 与写请求限定为 string、boolean 或安全整数。只读 TypeScript 类型已重新生成。
- REST 路径、权限键、数据库 Schema 和迁移均未改变；没有新外部写入或网络请求。
- 严格 lint 会拒绝过去“形式通过但 Store 无法执行或会忽略约束”的 Bundle，这是有意的 v1alpha1 契约修复。三份内置 Bundle 无内容变化，因此不需要提升定义版本或迁移摘要。
- Secret 即使从旧 Store/service 对象进入 HTTP 边界也不会回显；但开发 Secret 仍只保存在进程内存，不等同于生产加密、Secret Manager 或 Agent sealed handle。
