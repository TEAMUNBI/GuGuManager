# GM-20260808-006：Identity Web 与重置令牌收口

日期：2026-08-08

## 变更范围

本切片验收并加固首次 Setup、匿名密码重置、用户与 server membership 管理页面，同时修正会话探测、前端 Mock 与服务端密码重置签发语义；权威文档同步为已经存在开发 Web、但仍没有生产持久 Identity。

## 已实现

- 应用启动只有在 Session API 返回 `401 AUTH_REQUIRED` 时进入登录页；网络、依赖或服务端错误显示可重试错误，不再伪装成退出登录。
- Users 页面在用户或服务器选择变化时立即隔离旧 membership 快照，加载或失败期间不能对上一目标执行 Revoke，过期响应不能覆盖当前选择。
- 停用 active 用户、把 `platform_admin` 降为 `server_owner`、撤销 membership 都必须先确认明确的目标与即时影响；确认失败时 Modal 保留，API 不会在确认前调用。
- 角色按钮暴露 `aria-pressed`，用户状态点带独立的 `Status: active/disabled` 文本替代，不再只靠颜色表达。
- 浏览器 Mock 与服务端一致拒绝向 disabled 用户授予 membership 或签发密码重置令牌；后者返回 `OPERATION_CONFLICT`，不再让离线演示路径制造假绿。
- 密码重置令牌签发在生成任何明文前验证目标用户：缺失用户返回 `404 NOT_FOUND`，disabled 用户返回 `409 OPERATION_CONFLICT`，两种失败都产生开发审计且不会保存令牌。
- 真实 App 路由测试覆盖 Setup 提交、匿名 reset 提交及旧会话撤销提示、用户创建、一次性明文 Modal 关闭清理、membership 授予/撤销、危险操作确认、角色与状态无障碍语义。
- README、设计章节、贡献链接与阶段状态不再声称 Identity 没有前端；历史 GM 文件保持不变。

## API、数据库与权限影响

- OpenAPI 为管理员签发密码重置令牌补充 `404` 与 `409` 响应，成功请求和请求体不变。
- 没有新增迁移或持久数据；用户、令牌摘要、会话、membership 和审计仍在单进程内存中。
- 资源授权模型和权限键未改变；本切片强化的是目标隔离、失败语义和操作确认。

## 同日独立审查补充

- Membership PUT/DELETE 现在同时采用 mutation 期间禁用目标切换，以及提交目标快照、实时 scope ref 和响应身份复核。即使测试强制绕过 disabled 控件，旧用户或服务器的延迟成功/失败也不能污染当前授权视图。
- 当前 session 用户的全局角色按钮和内部请求入口都拒绝自我角色变更，避免 Users 页面目录记录与 App 根 session 角色失配；管理员必须改用另一个平台管理员会话执行此操作。
- 停用用户、撤销 membership 和管理员降级的 rejection 都在对应 dialog 内显示 `role="alert"`，保持 Modal 与焦点，恢复确认按钮以便重试，不再依赖 inert 根节点中的 toast 或被遮挡的页面错误。
- 新增回归后，`AppIdentity.test.tsx` 为 20/20；全量前端为 10 个文件、84 个测试，typecheck 与 build 通过。真实 Chromium E2E 另见 [GM-20260808-011](GM-20260808-011.md)。
