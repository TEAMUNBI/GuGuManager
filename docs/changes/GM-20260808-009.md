# GM-20260808-009：阶段 0 契约与迁移门禁

日期：2026-08-08

## 变更范围

本切片把 OpenAPI、Agent Protobuf 和 PostgreSQL 迁移从静态骨架提升为可重复的生成、漂移、兼容与数据库集成门禁，并补充固定版本依赖扫描。它不把这些契约误称为生产 Store、Agent Runtime 或 gRPC 实现。

## 已实现

- OpenAPI 使用 `@redocly/cli 2.46.0` lint，使用 `openapi-typescript 7.13.0` 生成并检查 `web/src/lib/openapi.generated.ts`；CI 在 PR 中通过 oasdiff 与目标分支比较 breaking changes。
- npm 对传递依赖固定 `js-yaml 4.3.1` 覆盖，消除安装审计中的高危问题；CI 执行 `npm audit --audit-level=high`。
- Agent Protobuf 按 Buf `STANDARD` 规则规范为 `api/proto/gugumanager/agent/v1/agent.proto`，服务与流消息采用 `AgentGatewayService`、`ConnectRequest`、`ConnectResponse` 命名；旧文件尚无生成消费者，因此在创建兼容基线前完成目录和符号规范化。
- Buf v2 配置固定 CLI `1.72.0` 与 Go 插件 `protocolbuffers/go v1.36.11`，生成 source-relative Go 类型，并提交 `api/proto/agent-v1.baseline.binpb`。
- CI 执行 Protobuf format/build/lint、仓库基线 breaking、全部 `api/proto/**/*.pb.go` 的已跟踪及未跟踪重生成漂移检查；PR 另与目标分支比较，避免只更新仓库 baseline 绕过审查。
- PostgreSQL 集成测试使用 `pgx/v5 5.10.0`，只接受显式 `GUGU_TEST_DATABASE_URL`，并在联网前要求数据库名有非空前缀且以 `_test` 结尾。
- 每次数据库测试创建随机唯一 Schema，顺序执行 `000001_core`、`000002_identity` up，断言关键表和 `server_members.updated_at`，验证摘要长度、用户状态、normalized email 唯一性与重置令牌过期约束，再逆序 down 并确认对象消失；defer 只清理本次 Schema。
- CI 使用 PostgreSQL 17 service 执行迁移测试，并固定 `govulncheck v1.6.0` 扫描可达 Go 漏洞。

## API、协议、数据库与依赖影响

- OpenAPI 的密码重置签发响应与生成的 TypeScript 类型同步；没有引入运行时请求/响应校验。
- Protobuf package 仍为 `gugumanager.agent.v1`，Go import 路径改为与 package 目录一致；这是首个受 Buf 管理的 baseline，Agent mTLS/gRPC 仍未实现。
- 新增测试依赖 `github.com/jackc/pgx/v5 v5.10.0` 与 Protobuf runtime `google.golang.org/protobuf v1.36.11`。
- 迁移 SQL 本身未因测试改写；Control Plane 仍使用内存 Store。
