# 01 产品范围

## 1. 产品定位

GuGuManager 统一管理 Linux 节点上的 Dedicated Server，覆盖节点、容器、端口、控制台、文件、指标和备份。游戏差异通过公开、版本化的 GameDefinition 表达，复杂能力通过受限 GameExtension 承载。

目标用户是自托管管理员、小型游戏托管团队和维护游戏定义的社区贡献者。首版采用单控制平面、单管理域模型；一个部署可以有多个管理员和服主，但不提供组织级多租户隔离、计费或经销商层级。

## 2. 目标

- 管理多个 Linux 节点和其上的 OCI 游戏容器。
- 提供创建、启动、停止、重启、控制台、文件、指标和备份恢复能力。
- 通过 GameDefinition 支持安装、配置、启动、更新和健康检查。
- 让 Control Plane、Agent、Web 和游戏包独立测试与发布。
- 让第三方在不修改 Control Plane 的情况下贡献游戏包。
- 对用户操作、Agent 任务和关键安全事件提供可追踪的审计链。

## 3. 非目标

首个公开版本不包含：

- 计费、订单、支付、优惠券、商城、工单和营销网站。
- 跨区域高可用控制平面、Kubernetes 自动扩缩容和自动节点放置。
- 跨节点在线迁移、Windows 节点、VM Runtime 和必须运行图形客户端的游戏。
- 插件或模组市场，以及未经审核的任意代码市场。
- 自动跟随 `latest` 的运行版本漂移。
- 组织、经销商或企业级多租户配额。

### 与 Pterodactyl 常见能力的范围对照

“类似 Pterodactyl”描述产品类别，不表示复制其全部功能。为避免实现者自行扩大范围，以下能力按首个公开版本明确归类：

| 能力 | 首个可用 MVP | 后续或非目标 |
| --- | --- | --- |
| 本地用户与服务器成员 | 管理员创建/停用用户、分配 server membership、立即撤销访问；当前已有内存 API 与开发管理页面 | 邮件邀请、自助注册、外部身份源 |
| `Network` | 查看与增删 Allocation、切换主端口，全部使用事务和 generation 前置条件 | Location、自动放置、跨节点迁移 |
| `Startup` | 查看解析后的启动命令、按 Schema 修改非 Secret/Secret 变量并触发 generation | 任意 Shell、未声明变量和浏览器端模板执行 |
| 文件访问 | 受授权的面板文件 API | SFTP/SSH 兼容入口、跨服务器文件同步 |
| 每服务器数据库 | 不包含 | 数据库主机池、凭据轮换和数据库生命周期 |
| 管理员挂载 | 不包含 | 审核后的只读/受限挂载策略；任意宿主路径永久非目标 |
| 定时任务与通知 | 不包含 | 阶段 4 |
| MFA、邮件密码恢复 | 不包含；当前开发 Web/API 已提供本地短期单次密码重置，但没有持久存储或邮件投递 | TOTP/WebAuthn、邮件恢复 |
| 用户 API Token | 不包含 | 稳定 REST 权限模型完成后提供 scope、到期和撤销 UI/API |
| 计费、工单、经销商 | 不包含 | 首个公开版本非目标 |

## 4. 支持游戏的边界

被支持的游戏必须同时满足：

1. 提供合法可部署、无图形界面的 Dedicated Server。
2. 支持当前 Agent 的操作系统和 CPU 架构。
3. 能由当前 Runtime Adapter 启动，首版为 OCI 容器。
4. 安装、启动、停止、端口、健康检查和持久化数据可由定义或受限扩展表达。

GUI 游戏、主机平台游戏和强依赖客户端反作弊的游戏不在首版承诺内。未来通过新的 Agent 或 Runtime Adapter 扩展，不把平台差异写入核心领域。

## 5. 角色

| 角色 | 职责 | 默认权限 |
| --- | --- | --- |
| 平台管理员 | 管理用户、节点、端口、游戏包、服务器和审计 | 全局基础设施与配置 |
| 服主 | 运维被分配的服务器 | 电源、控制台、指标、文件和备份 |
| 游戏包贡献者 | 维护独立仓库中的 GameDefinition 与扩展 | 不自动获得面板运行权限 |
| Node Agent | 执行节点任务并回报状态的服务身份 | 仅限绑定节点和被授予的能力 |

权限默认拒绝。资源列表、详情、实时通道和文件下载都必须在服务端重复执行授权，不能只依赖前端隐藏入口。

## 6. 版本范围

| 能力 | 开发垂直切片 | 首个可用 MVP | 后续 |
| --- | --- | --- | --- |
| 管理员登录和会话 | 种子管理员或受控内存初始化、Cookie 会话、CSRF、限流与撤销 | PostgreSQL 持久会话与 CSRF 会话恢复（已实现）、多副本一致撤销与密钥轮换 | 外部身份源 |
| 用户与服务器成员 | 本地用户管理页面、停用、单次密码重置、membership 与即时 REST 授权 | PostgreSQL 持久用户/令牌/membership 与资源授权（已实现）、生产管理页面与实时连接撤销 | 邮件邀请、外部身份源 |
| 节点 | 模拟注册和心跳 | mTLS 注册、证书轮换、能力协商、心跳与离线判定（已实现）、真实 OCI | 自动放置、排空 |
| 服务器 | 创建、列表、幂等电源任务 | 真实安装、启停、控制台命令与备份下载（已实现）；日志/指标经 PostgreSQL 持久化（000006 迁移），控制面重启可恢复 | 迁移和定时任务 |
| Network 与 Startup | 内存 Allocation、主端口切换、固定 Bundle Schema 变量编辑和模拟 reconcile | PostgreSQL Allocation 事务、真实端口绑定、Agent 对账和资源级授权（已实现）；加密 Secret 与多端口映射 | 自动端口策略、批量编排 |
| 文件与备份 | 安全路径和交互演示 | Agent 文件服务（含停止态容器写入与状态保持）和本地一致性备份/下载（已实现） | S3、保留策略 |
| 游戏包 | Schema 与声明式示例 | PaperMC、Factorio 一致性测试 | 官方 Catalog |
| Extension | 仅保留契约章节 | 不作为 MVP 示例依赖 | WASI/隔离 OCI Runner |

“开发实现”必须在配置和界面中有明确标识，不能用于互联网生产部署。

当前 Identity 开发适配器的用户、Bootstrap/reset 令牌摘要、会话和 membership 均保存在单进程内存中。它可以验证协议、安全状态迁移和资源授权，但不能替代 PostgreSQL 事务、Redis 协调、多副本撤销或长期运维恢复。

生产模式使用 PostgreSQL store 承载同一领域接口（编译期断言覆盖 Control Plane 全部契约方法），节点任务由真实 mTLS gRPC Agent 执行；开发模式仍保持上述内存/模拟边界，详见 [本地开发](../development/LOCAL_DEVELOPMENT.md)。概览页 CPU 与实时内存用量已由 PostgreSQL 聚合（`server_metrics` 表的 AVG/SUM），不再恒为 0；控制台日志与指标经 Agent `LogBatch`/`MetricsBatch` 帧双写内存缓冲与 PostgreSQL（日志每服务器保留最近 500 行、指标每服务器保留最近 60 点），控制面启动时从 DB 恢复，重启不丢失。生产模式其余已知限制：加密 Secret 静态存储、实时控制台 WebSocket、Outbox/多副本恢复尚未实现。
