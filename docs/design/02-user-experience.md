# 02 用户体验

## 1. 信息架构

### 当前开发切片

管理员主导航包含：

- `Overview`：模拟的全局容量、在线节点、运行服务器、事件和待处理任务。
- `Servers`：搜索、筛选、创建和进入服务器工作区。
- `Nodes`：模拟心跳、容量、版本、维护状态和分配使用量。
- `Game library`：开发目录中的游戏定义、审核状态、能力、平台和版本。
- `Users`：仅平台管理员可见的本地用户、角色、密码重置令牌与 server membership 管理。
- `Audit`：开发内存中的操作者、目标、结果、时间和 operation ID。
- `Settings`：会话安全说明和开发模式提示。

当前服务器工作区包含 `Overview`、`Console`、`Files`、`Backups`、`Network`、`Startup`、`Activity` 和 `Settings`。`Network` 与 `Startup` 已提供开发适配器页签，但只操作内存期望状态并等待模拟 `reconcile` operation；它们不是生产端口或 Runtime 配置界面。

1A Identity 当前同时提供 Control Plane REST API 和开发 Web 流程。未初始化的 Control Plane 先显示首次 setup；平台管理员可在 `Users` 页面创建、更新或停用本地用户，签发一次性密码重置令牌并维护 server membership；匿名重置页面负责消费令牌。默认快速启动仍进入已初始化的种子管理员登录页。

默认种子状态只有一个开发管理员，但管理员可以继续创建本地用户并分配服务器权限。前端按角色隐藏入口不构成权限隔离证明；当前 API 会对服务器列表、详情和受保护 REST 资源重新授权，生产 MVP 还必须覆盖实时通道、下载和后台任务。

列表、标题和创建选择器以已解析的上游游戏版本为主，例如 `PaperMC 1.21.8`。服务器详情同时展示 GameDefinition 版本和可复制的 Bundle 摘要；界面不得把这三者统称为“Bundle version”。

### 生产 MVP 目标

生产 MVP 保留上述导航，并补齐受控初始化、节点注册、真实 Bundle、节点与端口管理、`Network`、`Startup` 和按服务器授权的服主视图。生产能力不得静默回退到浏览器 Mock 或内存适配器。

## 2. 当前可演示流程

1. 使用明确标记的种子开发账号建立 Cookie 会话；未初始化的开发适配器会先显示首次管理员 setup，并原子消费 Bootstrap Token。
2. 查看种子节点、游戏目录和已有服务器。
3. 选择可用节点、已审核的开发游戏定义和资源配额，创建模拟服务器。
4. 轮询 provision operation，等待内存适配器把生命周期收敛为 `ready`。
5. 执行启动、停止、重启或强制终止，并通过 operation 查看模拟状态收敛。
6. 在 `Network` 中创建 Allocation、切换主 Allocation 或删除非主 Allocation，观察 generation 前置条件、operation 互斥和模拟对账。
7. 在 `Startup` 中编辑固定 Bundle 受限子集声明的字符串、整数、布尔、枚举和 Secret 变量；缺少 required 值时不能启动，Secret 只允许替换或清除，读取时不返回值或候选元数据。
8. 查看控制台快照、发送开发命令，在受限本地数据根中创建、编辑、移动和删除文件。
9. 创建模拟备份，并在服务器停止时演示恢复锁、摘要登记和异步删除状态机。
10. 在服务器 `Activity` 和全局 `Audit` 中查看开发审计记录。

Identity 的当前可演示流程可通过 Web 完成，并复用相同 API：读取 setup 状态并原子消费 Bootstrap Token、创建或停用本地用户、签发并消费一次性密码重置令牌、授予/替换/撤销服务器 membership。密码重置和用户停用会撤销该用户的旧内存会话；membership 变更立即影响服务器列表、详情和受保护 REST 资源。

该流程不创建持久生产管理员、节点注册令牌、证书、宿主端口绑定、容器或可恢复备份。Identity、Allocation 和 Startup 都是内存记录，Startup Secret 也没有加密持久化。进程退出后会重置用户、Bootstrap/reset 令牌摘要、会话、membership、服务器、operation、Allocation、Startup、备份元数据和审计；`GUGU_DEV_DATA_ROOT` 下的服务器文件会保留，因此动态创建服务器的旧目录可能在重启后成为不可达的开发孤儿目录，详见 [ADR-0002](../adr/0002-development-data-lifecycle.md)。

## 3. 生产 MVP 目标流程

1. 管理员通过受控初始化创建首个账号，初始化完成后永久关闭公开初始化入口。
2. 管理员创建一次性、短 TTL、绑定预期节点名称的注册令牌。
3. Agent 使用令牌提交 CSR，取得节点证书并建立出站 mTLS gRPC 连接。
4. 管理员审核并安装固定摘要的 GameDefinition Bundle。
5. 管理员选择节点、Bundle、资源、端口和所有者创建服务器。
6. Control Plane 在同一事务中写入服务器 generation、端口分配、provision 任务和 Outbox。
7. Agent 安装容器并回报 observedGeneration、observedAt、日志和指标。
8. 服主执行启动、停止和重启，使用实时控制台、文件服务与可校验备份。
9. 所有关键操作在服务器 `Activity` 与全局 `Audit` 中可追踪。

该流程只有在 [测试与路线图](11-testing-roadmap.md) 的生产验收全部通过后才可称为生产 MVP。

## 4. 页面状态

生产 MVP 的每个数据页面都必须提供：

- 初次加载骨架，不使用导致布局跳动的全局 spinner。
- 无数据空态和唯一、可执行的主操作。
- 局部刷新状态，并保留已经加载的可用信息。
- 结构化错误摘要、operation ID、是否可重试以及安全的下一步。
- 权限不足、资源不存在和节点离线的不同反馈。
- 危险操作确认，其中说明目标、影响和不可逆范围。

当前开发切片应尽量遵守相同交互语义，但尚不能作为权限隔离、真实故障恢复或生产可用性的验收证据。状态颜色只做辅助，文字、图标和可访问名称必须独立表达状态；动画遵守 `prefers-reduced-motion`。

## 5. 电源与任务交互

- 启动、停止和重启是异步操作，成功受理后返回 operation，不等待 Runtime 完成。
- 同一服务器存在互斥任务时，按钮保持稳定尺寸并显示当前动作；等价请求复用 operation，冲突请求返回现有 operation 信息。
- `restart` 是显式操作，不能简化为 desired power `running`。
- 节点离线、恢复中或删除中时，界面禁用不安全操作并显示原因。
- 乐观界面只表示“请求已受理”。开发切片的 observedPower 来自模拟收敛；生产 observedPower 必须来自 Agent 观测。

## 6. 控制台

当前开发切片通过 REST 返回有限控制台快照，并把命令写入内存日志；它没有 WebSocket、断线续传或真实进程标准输入。

生产 MVP 目标为：

- 首次连接先返回有限历史，再推送带递增序号的实时行。
- 客户端保存最后序号，断线重连时请求续传；缓冲区过期时收到明确的 reset 事件。
- 命令发送单行、限长、限频，并在服务端重新授权。
- 密钥、注册令牌和内部命令行不得出现在控制台回放中。

## 7. 文件与备份

当前开发切片可在 Control Plane 本机的受限开发数据根中列出、读取、原子写入、建目录、移动和删除文件，也可演示备份创建、停服恢复和异步删除。它没有 Agent 文件传输、流式上传/下载、解压、磁盘配额或真实备份归档，不能把元数据摘要称为制品校验。

生产 MVP 目标为：

- 文件浏览使用面包屑、名称排序和明确的文件类型，不显示宿主绝对路径。
- 编辑器在覆盖远端较新版本前提示冲突；写入采用临时文件、fsync 和原子替换。
- 上传显示单文件与总配额进度；解压是独立受审计操作。
- 恢复备份前停止服务器、取得恢复锁、校验摘要并要求二次确认。

## 8. Identity 与 Network/Startup 边界

- 当前 setup 页面通过 API 查询是否仍需首个管理员，并用短期 Bootstrap Token 原子创建平台管理员；令牌只保存 SHA-256 摘要，成功后立即消费并关闭 setup。
- 平台管理员可在 `Users` 页面查询、创建、更新或停用本地用户。停用用户会立即撤销其内存会话。
- 平台管理员可签发短期、只显示一次的本地密码重置令牌；匿名重置页面负责替换口令、拒绝过期或重放并撤销旧会话。服务端只保存令牌的 SHA-256 摘要。
- `Users` 页面通过服务器 membership API 查询、授予/替换或撤销权限，变更立即影响当前 REST 资源授权。生产目标仍需持久事务、多副本撤销，以及未来实时连接在授权变化后的主动关闭。
- 当前 `Network` 显示节点、绑定地址、端口、协议和主 Allocation。精确 endpoint 重复返回 `409 PORT_CONFLICT`，`0.0.0.0` 与 `::` 被开发适配器拒绝；这些检查不代表操作系统端口已经预留。
- 当前 Allocation 没有 `portRef`、容器端口或角色，因此只验收单端口开发演示。多端口 Bundle 映射、数据库唯一约束、真实 Runtime 绑定和绑定阶段冲突仍是生产目标。
- 当前 `Startup` 显示服务器固定 GameDefinition Bundle 解析出的只读命令和变量 Schema。普通变量显示当前值与默认值；Secret 只允许替换或清除，响应不含明文、默认值、const 或 enum 候选。required 值未配置时，Start/Restart 会在任何状态变化前失败。
- 当前 Network 或 Startup 写入使用十进制 generation 形式的 `If-Match`，成功受理后递增 generation，并通过模拟 operation 对账；过期编辑返回 `412 PRECONDITION_FAILED`。该 Header 还不是标准强 ETag。
- 生产实现必须增加资源级授权、PostgreSQL 事务、持久幂等、加密 Secret/Agent 句柄和真实 Runtime 对账；当前浏览器或内存行为不能替代这些验收。

## 9. 响应式和键盘行为

- 桌面端使用固定导航与高密度工作区，移动端使用可关闭的抽屉导航。
- 表格在窄屏转换为有标签的行，不依赖横向溢出完成主要操作。
- 所有菜单、对话框、标签页和控制台输入可使用键盘，焦点在打开和关闭后正确归位。
- 图标按钮有工具提示与可访问名称；触控目标不小于 44 x 44 CSS 像素。
