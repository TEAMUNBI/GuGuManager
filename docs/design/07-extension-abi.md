# 07 Extension ABI

## 1. 适用范围

GameExtension 只用于声明式 GameDefinition 无法可靠表达的能力，例如复杂版本解析、专有协议查询、存档转换或跨版本迁移。安装下载、模板渲染、参数绑定、常见健康检查和备份钩子优先使用内置声明式实现。

Extension ABI 属于阶段 3。阶段 0、阶段 1 和 MVP 参考包不得依赖尚未交付的扩展能力。

## 2. 运行模型

优先运行在 WASI Component Model 沙箱；无法适配 WASI 的扩展可运行在独立、非特权、只读根文件系统的 OCI Runner 中。禁止：

- Go 原生 `plugin` 或向 Control Plane 动态加载共享库。
- 向 Web 注入脚本、HTML、路由或任意组件。
- 直接访问宿主 Docker Socket、进程命名空间或任意文件。
- 自行读取 Secret 明文或把 Secret 写入日志与返回值。

## 3. Host API

首个 ABI 只暴露显式授权的能力：

- 在当前服务器数据卷内按目录句柄读取、写入和列举文件。
- 向 allowlist 中的主机发起有大小、时间和频率限制的 HTTPS 请求。
- 读取不透明 Secret 句柄并将其绑定到单次受控请求，不向扩展返回原始值。
- 输出结构化进度、检查点、诊断和生命周期结果。
- 读取经过裁剪的 Bundle、服务器资源、端口和版本上下文。

每个调用都带 operation ID、Bundle 摘要、ABI 版本和能力清单。Host API 不提供通用 Shell、任意进程派生或宿主路径接口。

## 4. 资源和安全限制

- 默认无网络、无文件、无 Secret；按调用授予最小能力。
- 限制 CPU、内存、执行时间、输出大小、文件数量、网络字节和调用频率。
- 输出经过 Secret 检测和大小裁剪；超限返回结构化 `HOOK_OUTPUT_LIMIT`。
- Runner 根文件系统只读，临时目录独立且任务后销毁。
- 扩展制品固定摘要、验证签名并记录来源、SBOM 和许可证。

## 5. 版本兼容

ABI 使用整数主版本和可协商能力。新增可选字段保持向后兼容；删除、重解释或扩大权限必须升级主版本并新增 ADR。

Control Plane 在安装 Bundle 时验证扩展 ABI 与所有目标 Agent 兼容。未知必需能力必须拒绝，不能静默降级。
